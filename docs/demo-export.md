# 示例长回答 A

第一段：这个工具要解决的是长回答被聊天时间线淹没的问题。

第二段：用户会针对长回答里的多个部分连续追问，每个追问的回答也可能成为新的长内容。

第三段：因此数据结构需要支持树，而不是只支持一个固定原文和一组平铺评论。

第四段：第一版可以先做 CLI 和 OpenCode 插件，验证保存、切段、提问、挂接回答、导出这些核心动作。

### 为什么需要树结构
Node: `ans_6b8e196a`
Parent question: 为什么这里要用树结构？

因为每个回答都可能再次成为新的长内容。如果只做平铺评论，用户很快会分不清当前问题来自哪一段、上一层问题是什么、这条回答又生成了哪些子问题。树结构可以保存来源路径，让 A -> a1 -> x1 这种关系一直清楚。
